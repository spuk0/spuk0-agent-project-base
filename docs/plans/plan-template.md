# Título del plan

## Objetivo

Indicar el resultado concreto que debe producir este plan.

## Punto de partida verificado

- Registrar hechos del repositorio, no supuestos.

## Decisiones necesarias

- [ ] Incluir solamente decisiones que bloqueen reglas de negocio o código.

## Pasos

1. Definir el incremento verificable más pequeño.
2. Implementar dentro de los límites documentados.
3. Ejecutar validaciones proporcionales al riesgo.
4. Actualizar la documentación afectada.

## Riesgos

- Registrar modos de fallo realistas y sus mitigaciones.

## Criterios de cierre

- [ ] Los criterios de aceptación tienen evidencia.
- [ ] Los builds y tests obligatorios pasan.
- [ ] La documentación relevante está sincronizada.
